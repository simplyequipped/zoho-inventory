# zoho command reference

Generated by `zoho docs --markdown`. Do not edit by hand.

## Hand-written groups

### items

Item catalog.

```
zoho items list [--sku X] [--name X] [--search X] [--status active|inactive] [--type inventory|service]
zoho items get <id|sku>
zoho items create --name N --sku S [--purchase-rate R] [--rate R] [--unit pcs] [--json file]
zoho items update <id|sku> [--purchase-rate R] [--rate R] [--name N] [--json file]
zoho items activate <id|sku> | deactivate <id|sku>
zoho items delete <id|sku> --yes
```

Identifiers: anything that takes an <id|sku> accepts a Zoho item_id (long
number) or a SKU. SKU matching is exact unless --fuzzy or settings.sku_match
is "fuzzy", in which case Zoho's sku_contains filter is used and exactly one
hit is required.

Fields (Zoho names, passed straight through in --json):

```
  name*             display name
  sku               your SKU; what Shopify sync matches on
  rate              selling price
  purchase_rate     cost (unit cost in the pricing sheet)
  unit              e.g. "pcs"
  item_type         inventory | sales | purchases | sales_and_purchases
  product_type      goods | service
  description, purchase_description
  reorder_level, vendor_id, brand, manufacturer
  initial_stock, initial_stock_rate   (create only)
```

Reference: https://www.zoho.com/inventory/api/v1/items/

### composite

Composite items (assemblies) and their bundles.

A composite item is a sellable SKU made from other items. Assembling it
("bundling" in Zoho's API) consumes the mapped parts and adds finished units
to stock. This is what ties a Shopify SKU to the parts that go into it.

```
zoho composite list [--sku X | --sku-contains X | --search X] [--status active]
zoho composite get <id|sku>                       full record incl. mapped_items
zoho composite parts <id|sku>                     just the parts table
zoho composite create --name N --sku S --rate R --part SKU:QTY [--part ...] [--json file]
zoho composite update <id|sku> [--rate R] [--purchase-rate R] [--part SKU:QTY ...] [--json file]
zoho composite activate|deactivate <id|sku>
zoho composite delete <id|sku> --yes

zoho composite assemble <id|sku> --qty N [--date YYYY-MM-DD] [--ref X] [--note X]
zoho composite bundles [<id|sku>]                 assembly history
zoho composite bundle <bundle_id>                 one assembly
zoho composite unassemble <bundle_id> --yes       delete an assembly (returns parts to stock)
```

--part takes SKU:QTY or ITEM_ID:QTY and may repeat. On update, passing any
--part replaces the whole parts list, so pass all of them.

assemble builds the line_items from the composite's mapped_items times --qty.
Zoho's docs do not show the bundle request body; the field names used here
(quantity_to_bundle, line_items[].item_id, quantity_consumed, is_completed)
are from third-party connectors and the Books API. If Zoho rejects the
request, set settings.bundle_qty_key to "quantity" and try again.

Reference: https://www.zoho.com/inventory/api/v1/compositeitems/

### adjustments

Inventory adjustments: correct stock on hand outside of sales and purchases.

```
zoho adjustments list [--limit N]
zoho adjustments get <adjustment_id>
zoho adjustments create --reason "text" --line SKU:+N [--line SKU:-N ...] [--date D] [--ref X] [--note X]
zoho adjustments delete <adjustment_id> --yes
```

--line is SKU:DELTA or ITEM_ID:DELTA. DELTA is the change, signed: +3 adds
three, -2 removes two. Zoho calls this quantity_adjusted. Quantity
adjustments only; value adjustments go through `zoho api`.

Reference: https://www.zoho.com/inventory/api/v1/inventoryadjustments/

### org

Organizations visible to this client.

### auth

One-time setup and status.

```
zoho auth init        interactive: client id, secret, grant code -> credentials file
zoho auth status      token expiry, organization, rate-limit usage
zoho auth refresh     force a new access token now
```

Setup, step by step
-------------------
1. https://api-console.zoho.com, Add Client, Self Client, Create.
2. Client Secret tab: copy Client ID and Client Secret.
3. Generate Code tab: scope, e.g.
       ZohoInventory.items.ALL,ZohoInventory.compositeitems.ALL,
       ZohoInventory.inventoryadjustments.ALL,ZohoInventory.settings.READ
   duration 10 minutes, any description. Create, then copy the code.
4. Run `zoho auth init` within those 10 minutes and paste all three.

The command exchanges the code, stores the refresh token (mode 600), then
calls /organizations and stores the organization_id. If more than one
organization is visible it lists them and asks which to use.

### api

Call any Zoho Inventory endpoint.

This is the escape hatch that makes every endpoint in the API reachable even
before it has a typed command. organization_id and auth are added for you.

```
zoho api GET /compositeitems
zoho api GET /items --param sku=RNODE-T3S3 --param status=active
zoho api GET /items --all                       # follow pagination, list key auto-detected
zoho api POST /items --json item.json
zoho api POST /items --data '{"name": "Battery 2000mAh", "sku": "BAT-2000"}'
zoho api PUT /items/123456000000012345 --data '{"purchase_rate": 5.75}'
zoho api DELETE /items/123456000000012345 --yes
```

Paths are relative to /inventory/v1. Write methods honor --dry-run and print
the request before sending when --verbose is set. DELETE requires --yes.

Reference: https://www.zoho.com/inventory/api/v1/

## Generic groups

Each has `list`, `get`, `create --json|--data`, `update ID --json|--data`, `delete ID --yes`, `do ID ACTION`, `fields`.

### salesorders

Sales orders. Shopify-synced orders show up here.

- path `/salesorders`, list key `salesorders`, object key `salesorder`, id `salesorder_id`
- fields (* required): `customer_id*`; `date`; `reference_number`; `line_items[]{item_id, quantity, rate}`; `notes`; `shipment_date`; `is_inclusive_tax`
- list filters: `search_text`, `status`, `salesorder_number`, `customer_id`, `date`, `reference_number`
- actions: `confirmed`, `void`, `markasopen`
- reference: https://www.zoho.com/inventory/api/v1/salesorders/

### purchaseorders

Purchase orders to vendors.

- path `/purchaseorders`, list key `purchaseorders`, object key `purchaseorder`, id `purchaseorder_id`
- fields (* required): `vendor_id*`; `date`; `reference_number`; `line_items[]{item_id, quantity, rate}`; `delivery_date`; `notes`
- list filters: `search_text`, `status`, `purchaseorder_number`, `vendor_id`, `date`
- actions: `issued`, `cancelled`
- reference: https://www.zoho.com/inventory/api/v1/purchaseorders/

### purchasereceives

Receiving against a purchase order; this is what adds parts to stock.

- path `/purchasereceives`, list key `purchasereceives`, object key `purchasereceive`, id `receive_id`
- fields (* required): `purchaseorder_id* (query param on create)`; `date`; `line_items[]{line_item_id, quantity}`; `notes`
- list filters: `search_text`
- reference: https://www.zoho.com/inventory/api/v1/purchasereceives/

### contacts

Customers and vendors.

- path `/contacts`, list key `contacts`, object key `contact`, id `contact_id`
- fields (* required): `contact_name*`; `contact_type (customer|vendor)`; `company_name`; `email`; `phone`; `billing_address{}`; `shipping_address{}`; `contact_persons[]`
- list filters: `search_text`, `status`, `contact_type`, `contact_name`, `email`
- actions: `active`, `inactive`
- reference: https://www.zoho.com/inventory/api/v1/contacts/

### itemgroups

Item groups: one product with attribute variants (color, band).

- path `/itemgroups`, list key `itemgroups`, object key `item_group`, id `group_id`
- fields (* required): `group_name*`; `unit`; `attribute_name1..3`; `items[]{name, sku, rate, purchase_rate, attribute_option_name1..3}`
- list filters: `search_text`, `status`
- actions: `active`, `inactive`
- reference: https://www.zoho.com/inventory/api/v1/itemgroups/

### locations

Warehouses / locations. Most line items accept a location_id.

- path `/locations`, list key `locations`, object key `location`, id `location_id`
- fields (* required): `location_name*`; `type`; `address{}`
- actions: `active`, `inactive`, `markasprimary`
- reference: https://www.zoho.com/inventory/api/v1/locations/

### packages

Packages created from sales orders, before shipment.

- path `/packages`, list key `packages`, object key `package`, id `package_id`
- fields (* required): `salesorder_id* (query param on create)`; `date`; `line_items[]{so_line_item_id, quantity}`
- list filters: `search_text`, `status`
- reference: https://www.zoho.com/inventory/api/v1/packages/

- path `/shipmentorders`, list key `shipmentorders`, object key `shipmentorder`, id `shipment_id`
- fields (* required): `salesorder_id*, package_ids* (query params on create)`; `date`; `delivery_method`; `tracking_number`
- list filters: `search_text`, `status`
- actions: `delivered`
- reference: https://www.zoho.com/inventory/api/v1/shipmentorders/

- actions: `active`, `inactive`, `invite`
- reference: https://www.zoho.com/inventory/api/v1/users/
